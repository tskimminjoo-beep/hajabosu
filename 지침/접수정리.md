# 접수 정리 지침

접수 원문 1건을 읽고 하자대장에 들어갈 항목으로 정리한다. 기준은 `data/업무설명_하자보수.md`.
※ 실습용 가상 업무.

## 범위

- **하는 것:** 원문에서 접수일·위치·공종·하자내용·긴급도를 뽑거나 판단한다.
- **하지 않는 것:** 접수번호, 조치기한, 공사번호·시공업체·보증 판정, 책임구분, 상태. 이것들은 코드가 규칙으로 계산한다. `data/공사정보.csv`는 보지 않는다.
- 원문에 없는 내용은 지어내지 않는다.

## 입력

- 접수 원문 1건(txt)과 그 파일명. 파일명은 `NN_YYYYMMDD_...txt` 형태.
- 원문은 현장 메모, 메일, 메신저 대화 등 형식이 제각각이다.

## 출력

**JSON 객체 하나만** 출력한다. 앞뒤 설명, 코드블록 표시, 주석을 붙이지 않는다.

```json
{
  "원문파일": "01_20261102_B1푸드코트_누수.txt",
  "접수일": "2026-11-02",
  "위치": "B1 푸드코트",
  "공종": "방수",
  "하자내용": "중앙 통로 3번 매장 앞 천장 누수, 마감재 얼룩",
  "긴급도": "긴급",
  "판단근거": "천장에서 물이 떨어짐(누수)",
  "확인필요사유": null
}
```

| 키 | 값 | 규칙 |
|---|---|---|
| 원문파일 | 문자열 | 입력 파일명 그대로 |
| 접수일 | `YYYY-MM-DD` | 아래 "접수일" 참고 |
| 위치 | `층 구역` | 아래 "위치" 참고 |
| 공종 | 문자열 | 아래 "공종" 참고 |
| 하자내용 | 문자열 | 40자 이내 요약 |
| 긴급도 | `긴급` / `높음` / `보통` | 아래 "긴급도" 참고 |
| 판단근거 | 문자열 | 공종·긴급도를 그렇게 본 원문 단서, 한 줄 |
| 확인필요사유 | 문자열 또는 `null` | 사람이 확인할 것이 있을 때만 적고, 없으면 `null` |

모든 키를 항상 포함한다. 알 수 없는 값은 빈 문자열 대신 `null`을 쓴다. 단, `공종`은 아래 규칙대로 후보를 적는다.

## 접수일

- 원문에 적힌 날짜를 쓴다. 없으면 파일명 앞의 날짜(`YYYYMMDD`)를 쓴다.
- 원문 날짜와 파일명 날짜가 다르면 원문 날짜를 쓰고 `확인필요사유`에 적는다.

## 위치

- 형식은 `층 구역`이다. 예: `B1 푸드코트`, `2F 화장실`, `1F 정문`.
- 매장 번호, 기둥 번호, 남녀 구분 같은 세부 위치는 위치가 아니라 **하자내용**에 적는다.
- 층은 `B1`, `B2`, `1F`, `2F` 식으로 통일한다. 구역명은 원문 표현을 따르되 `공사정보.csv`의 위치 표기와 맞춘다. 예: 원문 "5층 레스토랑가" → `5F 레스토랑가`.
- 층이나 구역을 알 수 없으면 `null`로 두고 `확인필요사유`에 적는다.

## 하자내용

- 40자 이내. 무엇이, 어디서(세부 위치), 어떤 상태인지 쓴다.
- 날짜, 인사말, 보낸 사람, 잡담은 뺀다.
- 원문이 말한 사실만 쓴다. 원인은 원문에 있을 때만 쓰고, 추측하지 않는다.

## 공종

아래 단서로 판단한다.

| 공종 | 원문 단서 |
|---|---|
| 방수 | 누수, 천장에서 물 떨어짐 |
| 타일 | 타일 들뜸·깨짐·줄눈, 바닥 기울기 |
| 전기 | 조명, 콘센트, 분전반, 누전, 전원 |
| 설비 | 배관, 배수 막힘, 급수, 수전 |
| 기계 | 자동문, 셔터, 주차 차단기, 엘리베이터, 에스컬레이터 |
| 도장 | 페인트 벗겨짐·변색 |
| 바닥재 | 에폭시, 바닥 코팅, 장판 |

- 위 7개 중 하나만 쓴다. 다른 공종명을 만들지 않는다.
- **원문만으로 알 수 없으면 후보를 `설비/타일`처럼 `/`로 함께 적고**, 담당자가 현장을 보고 정한다. 이때 `확인필요사유`에 왜 갈리는지 적는다.
- 단서가 하나도 맞지 않으면 `null`로 두고 `확인필요사유`에 적는다.

## 긴급도

| 긴급도 | 기준 |
|---|---|
| 긴급 | 누수, 전기 이상, 고객 안전 위험(넘어짐·미끄러짐·추락) |
| 높음 | 고객 출입·영업 지장(출입문·자동문·주차 출구 이상, 고객 시설 사용 불가, 고객 민원) |
| 보통 | 그 외(미관, 운영 지장 없음) |

- 해당하는 것이 여럿이면 가장 높은 단계를 쓴다.
- **고객 = 이용 고객.** 입점 매장(테넌트)의 문의·요청은 고객 민원으로 보지 않는다.
- 접수자가 안전 조치를 해둔 경우(안내 콘, 미끄럼 주의 표지판, 물받이)는 위험이 실제로 있다는 단서로 본다.
- 운영 지장 여부가 원문에 없으면 `보통`으로 두지 않고 `확인필요사유`에 적는다.

## 금지

- 규칙에 없는 값을 만들지 않는다 (공종 7종, 긴급도 3종 밖의 값).
- 보증 여부, 시공업체, 조치기한을 추측해서 쓰지 않는다.
- 사진·첨부 내용은 원문에 글로 적힌 것만 쓴다.
- JSON 외의 글을 출력하지 않는다.
